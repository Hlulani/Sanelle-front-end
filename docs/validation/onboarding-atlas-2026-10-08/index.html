Reference conflicts are visible here.

The atlas draws the same four priority choices on every onboarding screen, including name, diagnosis and date entry. The implementation keeps the atlas shell, photos, colours, typography, spacing, choice rows and buttons, while using the actual fields specified by the journey map. Back, demo/clear, logout and finish controls follow the journeys. Empty states really are empty, and progress uses valid step numbers.

The artboard’s phone bezel, notch and explanatory panels are export framing. They are excluded from the app. The rendered PDF’s DejaVu font is used for onboarding, rather than the different fonts named in its HTML.

Validation notes · Screen coverage

Priority screen · direct viewport comparison

The supplied HTML is rendered independently at the app’s viewport size, with the embedded PDF font and without export framing. Both browsers compare header, photo, eyebrow, heading, first choice, primary button and footer bounds to within 2 CSS pixels. This is a geometry check, not a claim that every screen is pixel-identical.
